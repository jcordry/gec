## Collision Detection 

- A rectangle test is very fast 

   - However, it can look a bit inaccurate 

   - One method that works well is to reduce each rect by about 10%  This is the method used in my game demo 

- Other methods exist 



- Circle – test against distance between two entities – if the distance is less than the sum of each entities’ radius a collision may have occurred  Accuracy depends on the shape of the entity 

- Use several rectangles per entity (requires prep.) 

- Have specific colliders 

- Do a pixel-by-pixel test

## Pixel Perfect Collisions 

- To determine pixel perfect collisions, we need to 

   - Initially carry out a rectangle collision test 

   - Determine the collision rectangle in both colliders 

   - Step through the rectangles (they must be the same size) and compare alpha values 

- A potentially more efficient way may be to 

   - Do a pre-process of textures determining a collision mask 

   - Can be packed into a bitfield with 0=passable and 1=solid 

   - This was the original way used but it is a bit of a pain doing the packing and unpacking and probably has negligible performance gain nowadays 





---

## Pixel Perfect 

###  Given this scenario 





- _After_ doing the basic rectangle test, determine the rectangle of collision 

>  This will be in screen space 

>  Transform it into each entities’ texture space 

>  Simply translate by - entity position 



>  Consider any frame offset as different frames will have different collision areas 

---

## Pixel Perfect 

>  Then work out start offsets and line offsets 

- Then loop through both areas 

- As soon as both have a transparency above a cut off then a collision has occurred 

>  E.g. transparency of >10 = collision – can tweak to taste 



---

## Ingredients 

###  We will need 

- To know the frame rectangle for both sprite at a particular frame number using a particular frame set 

- To be able to translate these to screen space and generate an intersection rectangle 

- Be able to read the raw texel data of the image 

- To be able to map this intersection rectangle into the texture space and get an offset into the image 

- Traverse both images checking when both pixels have an alpha value over a set amount

## Expanded 

- To work out the intersection rectangle you can 

   - Extract left as the maximum of the two, right as the minimum 

   - Top as the max and bottom as the min 

- Possible rectangle functions: 

   - Rectangle GetIntersectionWith(const Rectangle &other) 

   - Translate(int dx, int dy) 

- To get access to the raw pixel data in SFML: 

   - Create an sf::Image type and load the texture into that 

      - Best do at load time (same time you are loading a texture) 

   - Can then access the raw texels via Image::GetPixelsPtr 

      - It returns an array of bytes with 4 bytes per texel (RGBA)
